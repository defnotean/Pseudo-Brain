# Phase 2.6 Workstream C/D: Dynamic-K / lifecycle v0 — first result (2026-08-22)

**Design:** learned content-addressed activity gate (permutation-safe) with
load-balance pressure (soft floor 15%), sleeping slots decay toward identity
codes. Arms: fixed K=32 (reference, locked baseline recipe) vs dynamic gate,
6000 steps multitask, same seed/recipe. Data: Spark `runs/dynamic_k_v0_results.json`.

## Result [MEASURED]

| Arm | mean lift | tasks above chance+2% | active-K |
|---|---|---|---|
| fixed K=32 | −0.2261 | 0/25 | 32 (by definition) |
| **dynamic gate** | **−0.1553** | **2/25** | **32.0 (gate never closes)** |

Dynamic gate arm is better on mean lift (+0.071 absolute) and wins the
head-to-head on 14/25 tasks (vs 6 losses, 5 ties). Biggest gains exactly where
capacity/interference matters: t10 irrelevant-evidence +0.30, t05 two-hypotheses
+0.23, t12 weak-then-strong +0.23, t13 probabilistic-majority +0.20.

## Interpretation [LABELS]

[MEASURED] The gate arm improves multitask learning without any architecture
change beyond the lifecycle gate — consistent with the gradient-dilution
hypothesis for PB's multitask weakness.

[HYPOTHESIS] Mechanism unclear because **the gate never actually closed**
(active-K stayed at 32.0 throughout eval; telemetry shows it never went below
full open). The improvement therefore did NOT come from adaptive capacity
allocation — more likely from the gate acting as a learned per-slot residual
scale (a mild optimization-path change), or from the decay-toward-identity
dynamics during training.

[MEASURED] This means v0 does NOT yet demonstrate dynamic-K *as such* works:
the load-balance floor (≥15%) plus sigmoid saturation kept everything awake.
The result is best read as "learned slot-wise modulation helps" — a positive
signal for lifecycle work, but the core question (does capacity adaptation help?)
remains unanswered.

## Next steps for this workstream

1. Instrument per-slot gate values over training (are they all pinned near 1?)
2. Stronger sparsity pressure / temperature annealing so the gate can actually close
3. If gates still won't close: the task set may not reward sleeping slots — test
   on escalation task where Phase 2 showed spare-capacity effects
4. Re-test collapse resistance only after genuine active-K variation exists
