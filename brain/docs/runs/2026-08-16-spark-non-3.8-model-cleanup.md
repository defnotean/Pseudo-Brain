# Spark disk cleanup of non-3.8 models (2026-08-16)

Status: operational host cleanup while the live RCQ-v2 reference was running.
No qualification files, pins, releases, or TEST ranges were touched.

## Why

The Spark root filesystem was 98% full with about 21 GiB free, which is the
training disk gate. Cached chat weights that were not Qwen 3.8 filled most of
`/home/defnotean`.

## Kept

- `irene-voice/models/Huihui-Qwen3.8-27B-abliterated` (52 GiB)
- `irene-voice/models/Huihui-Qwen3.8-27B-abliterated-NVFP4-MTP` (27 GiB)
- `irene-voice/models/Qwen3-TTS-12Hz-0.6B-Base`
- `irene-voice/models/whisper-large-v3-turbo`
- `irene-voice/models/MiniMax-Music3` (music, 54 GiB)
- Docker `vllm/vllm-openai:nightly-aarch64` (in use by the reference train)
- Docker `lmsysorg/sglang:qwen38-27b`

## Removed

Idle DeepSeek, Ling, Muse Glimmer, and Qwen 3.5/3.6 weight trees under
`~/models` and `~/irene-voice/models`, the Qwen 3.6 Hugging Face cache,
DeepSeek KV cache, unused images `ghcr.io/aeon-7/aeon-vllm-ultimate:latest`
and `lmsysorg/sglang:latest-cu130`, and 36 GiB of Docker build cache.

Root-owned `~/.cache/huggingface/hub/models--Qwen--Qwen2.5-Omni-3B` (12 GiB)
could not be removed without sudo.

## Result

Disk went from about 21 GiB free (98% used) to about 552 GiB free (37% used).
The live train `dgx-rcq-v2-reference-seed-1702` stayed up.
